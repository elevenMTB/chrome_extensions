# Tab Group Helper 产品文档

## 1. 产品概述

### 1.1 项目背景

浏览器标签页数量增多后，用户需要频繁手动整理标签分组、跨窗口迁移标签、重复打开历史工作页，成本较高。`Tab Group Helper` 目标是作为一个仅供个人使用的 Chrome 插件，通过可配置规则自动对标签页进行分组，并支持历史分组与标签的复用、恢复和整理。

### 1.2 产品目标

一期目标：

1. 支持通过可视化页面配置标签自动分组规则。
2. 在标签创建、更新等关键时机自动判断并执行分组。
3. 支持同名分组在多窗口下的复用策略。
4. 支持复用历史同名分组，并对历史标签保留策略可配置。
5. 支持保存规则、分组元信息和标签快照，便于后续恢复和持续使用。

### 1.3 目标用户

- 当前阶段仅面向插件作者本人使用
- 偏重高频多标签、多系统、多工作流切换场景

### 1.4 一期非目标

- 不做云同步
- 不做多人共享规则
- 不做正则匹配
- 不做复杂推荐算法或 AI 自动分类
- 不做跨浏览器兼容，优先支持 Chrome

## 2. 核心使用场景

1. 用户打开新标签页时，插件自动根据规则将其归入已有分组或创建新分组。
2. 用户切换页面或页面标题加载完成后，插件重新判断该标签是否需要迁移到其他分组。
3. 用户在多个浏览器窗口同时工作时，插件根据配置决定同名分组是否合并到唯一实例。
4. 用户下次打开浏览器时，希望沿用历史分组名称、颜色和标签集合。
5. 用户需要手动维护规则，调整优先级、启停规则、修改颜色策略。

## 3. 功能范围

### 3.1 规则管理页面

插件提供独立配置页面，用于管理分组规则。

页面能力：

1. 展示全部规则列表。
2. 支持新增、编辑、删除规则。
3. 支持启用或禁用单条规则。
4. 支持拖拽或按钮调整规则优先级。
5. 支持查看每条规则的命中条件、分组名、颜色策略、状态。
6. 支持保存后立即生效。

### 3.2 规则模型

一期建议采用“分组规则”作为最小配置单元。

每条分组规则包含：

- `id`：规则唯一标识
- `enabled`：是否启用
- `priority`：优先级，数值越小优先级越高
- `groupName`：目标分组名
- `ruleName`：规则显示名称
- `colorMode`：颜色模式，`fixed` 或 `random`
- `fixedColor`：当颜色模式为固定时使用的颜色
- `matchMode`：组内条件关系，一期默认 `OR`
- `conditions`：匹配条件数组

每个匹配条件包含：

- `target`：匹配对象
  - `hostname`：域名部分
  - `url`：完整 URL
  - `title`：网页标题
- `operator`：匹配方式
  - `contains`
  - `startsWith`
  - `endsWith`
  - `equals`
- `value`：关键字

说明：

1. 一条分组规则可配置多条条件。
2. 一期条件关系明确为“任一命中即命中该规则”，即 `OR`。
3. 后续二期可扩展：
   - 条件关系 `AND`
   - 正则匹配
   - 排除条件

### 3.3 自动分组处理

插件在以下事件触发时自动执行规则匹配：

1. 新建标签页
2. 标签页 URL 更新
3. 标签页标题变化后可重新判断
4. 标签页从一个窗口移动到另一个窗口
5. 浏览器启动后执行一次初始化整理

自动处理流程建议如下：

1. 获取标签的当前 `url`、`hostname`、`title`。
2. 按规则优先级从高到低匹配。
3. 命中第一条启用规则后停止继续匹配。
4. 判断目标分组是否已存在。
5. 若存在，则将标签移入该分组。
6. 若不存在，则创建分组并设置名称与颜色。
7. 保存最新分组和标签快照。

### 3.4 优先级规则

1. 优先级按规则列表顺序或显式数值表示。
2. 多条规则同时命中时，仅执行优先级最高的一条。
3. 若标签已在其他分组中，后来命中更高优先级规则，则迁移到新的目标分组。
4. 禁用规则不参与匹配。
5. 未命中任何规则时，不自动分组。

### 3.5 分组颜色策略

每条规则支持配置分组颜色：

1. 固定颜色
2. 随机颜色

一期建议：

1. 随机颜色在“首次创建该分组”时生成一次并持久化。
2. 同名历史分组被复用时，优先沿用历史颜色。
3. 若规则从固定颜色切换为随机颜色，仅对后续新建分组生效，是否批量改历史分组颜色不纳入一期。

### 3.6 同名分组跨窗口策略

用户可在全局设置中配置同名分组策略。

支持两种模式：

1. `single-instance`
   - 同名分组全局只保留一个
   - 若新命中的标签出现在其他窗口，则自动移动到已有同名分组所在窗口
   - 若已有多个同名分组，插件按规则选择一个主分组并合并
2. `multi-instance`
   - 允许不同窗口保留同名分组
   - 分组显示名自动补后缀，如 `文档(1)`、`文档(2)`
   - 内部逻辑名称仍可保留原始组名 `文档`

一期建议默认值：`single-instance`

原因：

1. 更符合“同类工作流集中管理”的目标
2. 更利于复用历史分组
3. 更利于避免重复分组泛滥

### 3.7 历史分组复用

每次处理标签时，插件需要先检查当前浏览器中是否存在历史同名分组。

复用逻辑建议：

1. 优先查找当前打开窗口中的同名分组。
2. 若全局策略为 `single-instance`，再查找其他窗口中的同名分组。
3. 若找到同名分组，直接复用该分组 ID，不重复创建。
4. 若未找到，则创建新分组，并记录到本地存储。

### 3.8 历史标签保留策略

用户可配置同名历史分组中的历史标签是否默认保留。

支持两种模式：

1. `keep`
   - 关闭浏览器或标签后，保留该分组的历史标签快照
   - 浏览器重新启动时，不主动恢复任何历史标签
   - 当用户后续再次打开一个命中该分组规则的新标签时，若复用到该历史分组，则同时恢复历史快照中的标签
   - 示例：分组 A 曾包含网页 1、2；浏览器关闭后未自动恢复；重新打开满足分组 A 规则的网页 3 时，插件复用分组 A，并补开网页 1、2
2. `clear`
   - 复用历史分组时，清空历史标签记录
   - 当前仅保留本次命中的最新标签集合

一期明确产品定义：

1. “保留历史标签”不等价于“浏览器启动时自动恢复历史标签”。
2. 历史标签恢复的触发时机，是“该分组再次被命中并被复用时”，而不是浏览器启动时。

## 4. 数据设计建议

### 4.1 本地存储

一期建议全部使用 Chrome 本地存储：

- `chrome.storage.local`

建议存储内容：

1. `rules`
   - 规则列表
   - 优先级顺序
2. `settings`
   - 同名分组策略
   - 历史标签保留策略
   - 自动分组总开关
   - 是否开机初始化整理
   - 是否对已固定标签生效
3. `groupSnapshots`
   - 组名
   - 逻辑组 ID
   - 颜色
   - 最近窗口 ID
   - 最近分组 ID
   - 标签快照列表
   - 最近更新时间
4. `runtimeLocks`
   - 防止重复处理同一个标签的短期状态

### 4.2 推荐数据结构

```json
{
  "rules": [
    {
      "id": "rule-docs",
      "enabled": true,
      "priority": 10,
      "ruleName": "飞书文档",
      "groupName": "文档",
      "colorMode": "fixed",
      "fixedColor": "blue",
      "matchMode": "OR",
      "conditions": [
        {
          "target": "hostname",
          "operator": "contains",
          "value": "larkoffice.com"
        },
        {
          "target": "title",
          "operator": "contains",
          "value": "文档"
        }
      ]
    }
  ],
  "settings": {
    "autoGroupEnabled": true,
    "sameNameGroupPolicy": "single-instance",
    "historyTabPolicy": "keep",
    "runOnStartup": true,
    "includePinnedTabs": false
  }
}
```

## 6. 处理细节与边界规则

### 6.1 推荐的一期处理原则

1. 标签命中规则后，如果已经在目标分组中，则不重复移动。
2. 若标签当前处于其他分组，且后来命中更高优先级规则，则迁移到新分组。
3. 为避免抖动，针对同一标签短时间内重复更新，应增加去重节流。
4. 标题常常晚于 URL 加载完成，一期应支持 URL 命中后先分组，标题变更后再补充重判。
5. 固定标签页默认不处理。

### 6.2 需要重点处理的边界情况

1. `chrome://`、扩展页、本地文件页等特殊页面可能无法正常分组或不应处理。
2. 新标签页在加载早期 URL 为空或标题为空，需要延迟判断。
3. 某些网站会频繁改标题，容易引发重复移动。
4. 标签关闭后，快照中的历史标签需要及时清理失效状态。
5. 分组被用户手动重命名后，插件需要决定是否覆盖名称。
6. 分组被用户手动改颜色后，插件需要决定是否覆盖颜色。
7. 用户手动拖动标签到其他分组后，插件是否再次抢回，需要明确。

一期建议默认策略：

1. 不处理特殊系统页。
2. 用户手动修改分组名、颜色或标签归属后，后续规则处理仍允许覆盖。
3. 若规则要求迁移，则不保留对手动操作的让步窗口。

## 7. 技术方案建议

### 7.1 插件形态

建议使用 Chrome Extension Manifest V3。

模块建议：

1. `service worker`
   - 监听标签事件
   - 执行规则匹配
   - 调用分组 API
   - 管理本地存储
2. `options page`
   - 规则管理页面
   - 全局设置页面
3. `popup`
   - 快速查看当前标签命中的分组
   - 自动分组总开关
   - 手动触发“按当前规则整理当前窗口”
   - 手动触发“按当前规则整理全部窗口”

### 7.2 可能需要的权限

- `tabs`
- `tabGroups`
- `storage`
- `sessions`

视实现再评估是否需要：

- `alarms`
- `windows`

### 7.3 推荐事件监听

- `chrome.tabs.onCreated`
- `chrome.tabs.onUpdated`
- `chrome.tabs.onMoved`
- `chrome.tabs.onAttached`
- `chrome.tabs.onRemoved`
- `chrome.runtime.onStartup`

## 8. 一期 MVP 定义

### 8.1 必做

1. 规则管理页面可增删改查
2. 规则支持启停和优先级
3. 支持三类匹配对象：域名、完整 URL、标题
4. 支持四类匹配方式：包含、前缀、后缀、全等
5. 支持每条规则多条件
6. 支持固定颜色和随机颜色
7. 支持标签创建和更新时自动分组
8. 支持自动分组总开关
9. 默认不处理固定标签页
10. 支持同名组单实例或多实例策略
11. 支持历史同名分组复用
12. 支持历史标签保留或清空
13. 支持手动整理当前窗口和全部窗口
14. 支持分组规则 JSON 导入和导出

### 8.2 可延期

1. 操作日志查看
2. 正则匹配
3. 条件 `AND`
4. 黑名单规则

## 9. 风险与限制

1. Chrome 对标签页和分组的事件触发较频繁，若不做去重，容易重复处理。
2. 标题匹配依赖页面完成一定程度加载，命中存在延迟。
3. 跨窗口移动标签会影响当前工作流，若默认策略过强，使用体验可能打断用户。
4. 浏览器重启后分组与标签恢复行为受 Chrome 自身会话恢复机制影响，需要做兼容处理。
5. 若本地存储结构频繁变更，后续需要考虑配置迁移。

## 10. 已确认决策

以下产品决策已经确认，可直接进入技术设计与开发：

1. 多条件之间采用“任一命中即满足分组条件”。
2. 标签后续若命中更高优先级规则，需要迁移。
3. 默认不处理固定标签页。
4. “保留历史标签”不等于“启动时自动恢复历史标签”；只有该分组再次被命中并复用时，才恢复历史标签。
5. 多实例模式下的后缀仅用于展示层，不作为内部逻辑组名。
6. 不需要尊重用户手动调整，后续规则处理可直接覆盖。
7. 需要自动分组总开关。
8. 需要手动整理入口，且支持“当前窗口”和“全部窗口”。
9. 需要支持分组规则 JSON 导入和导出。
